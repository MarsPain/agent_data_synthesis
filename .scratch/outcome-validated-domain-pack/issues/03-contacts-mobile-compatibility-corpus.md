# 03 — Freeze and Preserve Contacts and Mobile Compatibility

**What to build:** Materialize the bounded, hash-manifested Contacts and Mobile compatibility corpus, independently reviewed expected canonical projections, and scoped readers/adapters that report readability, runnability, semantic equivalence, and current evidence admissibility separately.

**Blocked by:** [01 — Establish canonical Domain Pack identity and planning contracts](01-canonical-identity-and-planning-contracts.md)

**Status:** ready-for-agent

**Assignee:** Unassigned

**Parent spec:** [Outcome-Validated Domain Pack](../../../docs/product-specs/outcome-validated-domain-pack.md)

## Acceptance criteria

- [ ] The corpus manifest freezes the selected 26 checked-in Contacts/Mobile profiles by path, schema, digest, and byte count at one declared cutoff.
- [ ] One reviewed synthetic valid version-3 bridge profile per domain is clearly labeled synthetic compatibility evidence rather than historical input.
- [ ] Four self-contained golden chains cover Contacts and Mobile historical version-1 and mutation-aware version-2 manifests, reports, release packs, and every referenced dependency.
- [ ] Legacy inputs and expected canonical projections are independent checked-in fixtures and are not generated by the reader, adapter, or writer under test.
- [ ] Every corpus row declares four independent expected compatibility axes and bounded reason codes.
- [ ] Supported profiles compile deterministically to canonical Domain plans with exact logical pack, legacy runtime, original hash, selected mapping, and migration lineage.
- [ ] Bad license, bad schema, missing source, unsupported network work, ambiguous or unknown labels, cross-pack references, and tampered dependencies fail closed for their frozen reasons.
- [ ] Canonical outputs emit no fixture/domain/task/held-out aliases in semantic fields while preserving exact legacy-named runtime ids only in runtime fields.
- [ ] Golden chains reproduce their original historical decisions and are always historical-only/insufficient for current Release Candidate, Publishable, and Training Recommended claims.
- [ ] An injected unknown semantic label fails the complete corpus rather than being ignored or defaulted.

## Scope guard

Do not turn Contacts or Mobile into additional end-to-end tracer domains, expand
their coverage catalogs, rewrite historical bytes, or infer missing current
capability evidence from task names, tool traces, or old passing statuses.
